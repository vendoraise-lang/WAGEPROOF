# Factory MVP

Separate Worker and SQLite-backed Durable Object, in the existing repository to reuse authenticated Git access and pinned Wrangler. Proposal Preflight remains an independent Worker and application. No extra repository/account setup is needed. This is an observed experiment system, not a revenue-generating autonomous CEO.

## Market policy

Target market: United States; pricing/economics: USD; acquisition/SEO: US English and US buyers. Operator jurisdiction: Morocco, assessed separately for payment eligibility and payouts. Global sources are not verified US demand; the exploratory feed no longer gives a US demand score from worldwide discussion counts. Existing metrics do not identify visitor country. $1M annual revenue is an aspiration, not earnings. registry.json and commercial.json preserve this policy for future cycles.

## Cycle

1. A scheduled job reads up to 10 public Server Fault SLA questions once/day, with public GitHub SLA issues as a fallback when rate-limited, preserving URLs, timestamps, views/answers and CC BY-SA attribution. Missing sources remain missing. Indirect interest is not paid demand. Weighted scores expose assumptions; no opportunity auto-launches.
2. `node factory/build.mjs` generates a working SLA Preflight artifact from tested product code, plus one original educational resource draft. Artifacts are ignored, repeatable, and hashed. A preview can run locally with `FREE_BETA=true PAYMENT_MODE=test PORT=3001 PUBLIC_BASE_URL=http://127.0.0.1:3001 node factory/artifacts/sla-preflight/server.js`.
3. `python factory/release.py candidate` refuses until registry candidate has `publication: approved` and `approval: {actor: founder, artifactDigest: <exact SHA256>, approvedAt: <timestamp>}`. Founder must approve any increased product cap. Register the new product in `products` before deploying operations and product; the builder excludes that same ID when checking capacity. The gate checks the regenerated artifact, so stale approvals cannot authorize changed content. The approval file is an operator-controlled workflow gate, not a cryptographic identity proof; the agent must never self-authorize founder approval. There is no Git push-triggered deploy or automatic code deployment.
4. Existing Proposal Preflight records aggregate pageviews, completed reviews, downloads and request errors through an account-owned service-binding RPC. No public analytics-write API exists on the factory; browser download events are bounded and validated by the product. Known bots filtered, test traffic segregated, no IP/user IDs/document contents stored. Counts are events, not unique visitors. The product can record anonymous problem signals after confirmation; no contact details, message text or individual replies. Three signals produce a review recommendation. No support inbox is connected.
5. Fifteen-minute cron checks product health and payment-disabled configuration, refreshes sources daily, prunes events after 90 days and generates recommendations. Public dashboard shows 30 days. No active Codex session required. Initialization also runs once on first snapshot request; invocation type is recorded separately from actual cron.
6. At 30 days and >=100 pageviews, fewer than 3 review events pauses analysis. At 60 days and <100 pageviews, pause for failed acquisition. Three failed health checks produce a repair recommendation. Every operational run also verifies actual numeric analysis with a clearly synthetic, test-tagged request. Intentionally paused experiments skip that probe. Threshold-based restart needs a reviewed registry change. Product remains independently deployed; removing its optional service binding detaches it from the factory. Analytics outages fail open, so telemetry cannot take the product down. Factory can pause analysis, not undeploy code.

## Operations and release

`npm test`; `npm run check`; `node --check factory/worker.js`; `node --check factory/public/dashboard.js`.
`XDG_CONFIG_HOME=/tmp/preflight-cf-config WRANGLER_SEND_METRICS=false npx --no-install wrangler dev --config factory/wrangler.jsonc --port 8790 --test-scheduled`.
Local workerd verifies storage/dashboard, but outgoing network access can differ from production. Use live observations for health/evidence claims.
`python factory/release.py plan` is read-only. `operations` deliberately deploys the free Worker/SQLite object and cron; `existing-product` deploys only approved existing application changes. Both run tests first and require the secure Cloudflare binding. Pipeline never calls upgrades, billing, GitHub creation, outreach or payment activation APIs.

Costs/revenue: registry `costs` accepts USD integer `amountCents` with operator provenance/date/category. Do not include secrets or personal invoice details. These are operator-reported, not provider-verified. No payment account is connected; verified transactions/revenue are zero, profit remains unknown. Optional POST /api/payments/stripe-test requires a securely configured Stripe webhook secret, verifies raw-body HMAC, timestamp, product and amount, rejects live receipts, deduplicates test sessions and excludes them from revenue. No secret is configured and no artificial receipts were sent to production. Codex development credits and founder time must be allocated before profitability can be evaluated. Live provider integration is a separate approved task once a legitimate eligible account exists; this MVP cannot accept money.

## Cost envelope

No recurring AI calls. Estimated platform cash cost $0 within Cloudflare Free quotas. One SQLite Durable Object; 96 scheduled runs/day, 288 health/config/analysis requests plus one source fetch/day. Telemetry adds about one DO request/write per tracked event and one access read per analysis; usage grows with traffic. Free overages fail, not auto-upgrade. Cloudflare Free: Workers 100,000 requests/day, 10ms request CPU; Durable Object Free limits apply independently. Exact billing entitlement cannot be read by the existing scoped token; do not claim provider-invoice cost verification. No paid resources or subscriptions are configured.

Sources: https://developers.cloudflare.com/workers/platform/pricing/ and https://developers.cloudflare.com/durable-objects/platform/pricing/ (official source retrieved 2026-10-11). Public signal API: https://api.stackexchange.com/docs/questions . No paid API key required; obey returned backoff and quota.

## Limitations

No paid-demand proof, automatic customer acquisition, unique-visitor counting, personal support inbox, live payment processor, guaranteed search traffic or profit. The single resource in factory/resource.json is founder-approved and publicly served at /resources/sla-checklist; edits invalidate its exact-content approval. Its SHA256 covers its title, text and destination link. To publish /resources/sla-checklist, founder must explicitly approve that digest; only then may publication/approval fields be changed and a controlled operations release run. Resource visits and attributed product views, reviews, downloads and nonbinding price-interest events persist in a fixed-label funnel, with separate test counts. The 30-day zero-cost experiment is evaluated on each cron: 10 referrals, 10 attributed reviews and 3 nonbinding interest clicks justify payment-readiness review only; otherwise stop channel investment/scaling. Referral events use only the fixed source=sla-checklist label; no arbitrary referrer data is retained. Founder approval is required to publish or send distribution assets. Public dashboard contains only aggregates/public evidence. Tagged tests and recognized sample/operator traffic are excluded from non-test counters; untagged or spoofed traffic cannot be proven genuine. Additional product publication remains gated.

Commercial evidence and the sole selected existing-product experiment: commercial.json. Provisional Lemon test checkout request adapter: ../payments/lemon.js, contract-tested against the official SDK; not wired into HTTP routes, delivery or verified receipts. Official documentation now lists Morocco for bank payouts and verifies fees/holds; actual operator/store/product approval, bank access and test account connection remain pending. No live or provider-hosted checkout has been tested. See ../PROJECT.md for cited provider facts and the remaining test-account connection.
